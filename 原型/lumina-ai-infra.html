01 · Overview

§1 产品概览

1.1 · 产品定位

Lumina 墨光的 AI 能力此前依赖 ai_gateway（模型池 / 调用日志）、ai_chat（多轮对话）与 ai_grade（AI 批改）三个模块，属于「直连大模型」形态。D-09 在此之上补齐 AI 基础设施层：让回答有据可查（RAG 知识库检索增强）、让 AI能做事（Agent 工具调用编排）、让内容先审后发（多级内容审核流水线）、让服务永不裸挂（多厂商降级策略）。

本文档定义 D-09 的需求范围与业务流程（§4 为流程图核心章节），对应后端模块 ai_infra（路由前缀 /api/v1/ai-infra）。

⚖️ 合规域识别（需求阶段合规预检结论）
命中合规域：AI 生成内容（《生成式人工智能服务管理暂行办法》：AI 标识、内容审核）、个人信息处理（《个人信息保护法》：提问内容最小化留存）、未成年人保护（学生端提问需过滤不适内容）、算法推荐（知识库检索排序属算法应用，提供可解释与关闭路径）。以上合规域已转化为 §3 验收标准与 §7 合规章节。

1.2 · 范围与边界

03 · Functional

§3 功能需求与验收标准
📚
FR-1 · RAG 知识问答 P0
  • 教师 / 管理员可创建知识库，向其中添加文本分块（chunk），入库时调用 Embedding 服务（百川）生成向量。
  • 用户提问后：问题向量化 → 检索 knowledge_chunks → 相似度高于阈值取 Top-K 上下文 → 构建 Prompt → 调用 LLM（通义千问 / 智谱 GLM）→ SSE 流式返回。
  • 检索无命中（低于阈值）时明确提示「无相关知识」，可转通用回答或人工。
  • 每条回答支持点赞 / 点踩反馈，点踩可选填原因，落库用于质量分析。
验收标准（AC）
AC1: 知识库 CRUD 与分块添加可用，向量随分块入库 · 测试方法 🧩 API
AC2: 命中场景下 Top-K 上下文注入 Prompt，回答附带引用来源 · 🧩 API + 🖐️ Manual
AC3: 未命中场景返回「无相关知识」提示，不编造 · 🧩 API
AC4: 赞/踩反馈落库，点踩原因可选 · 🧩 API
AC5: AI 生成内容已打标识（前端标注「AI 生成，仅供参考」）· ⚖️ Comp
🤖
FR-2 · Agent 工具调用 P0
  • 管理员注册工具（agent_tools）：知识库检索、数据库查询、外部 API 调用、代码执行（沙箱）。
  • 用户与 Agent 对话时，LLM 决定调用工具 → 执行 → 结果回填上下文 → 继续推理，直至给出最终回答。
  • 每次会话生成 agent_sessions 记录，含消息轨迹与工具调用详情，可追溯。
  • 工具调用失败时进入失败态，支持重试；连续失败可放弃并提示用户。
验收标准（AC）
AC6: 工具列表可查询，注册的工具可被会话调用 · 🧩 API
AC7: 会话状态机按 §4.2 流转，全轨迹落库 · 🧩 API + 🖐️ Manual
AC8: 代码执行工具运行于受限沙箱，无越权文件系统访问 · 🔒 Sec
AC9: 危险工具（写操作）需二次确认 · 🖐️ Manual
🛡️
FR-3 · 内容审核流水线 P0
  • 用户内容（作业 / 讨论 / 笔记）发布前统一经 /ai-infra/moderation/check 审核。
  • 三级流水线：规则引擎预审（敏感词 / 正则 / 黑名单，毫秒级）→ 内容安全模型判定（通义 / 智谱，返回 safe + confidence）→ 低置信度转人工复核。
  • 所有审核结果写 moderation_logs（passed / blocked / reviewing），管理员可查日志并复核。
  • 拦截与转复核均通知用户；转复核同步通知管理员（notification 模块）。
验收标准（AC）
AC10: 规则命中即时拦截并记录 blocked，用户收到原因提示 · 🧩 API
AC11: 模型判定安全 → passed 放行；不安全 → reviewing 转人工复核并通知管理员 · 🧩 API
AC12: 审核日志仅管理员可查（越权返回 403）· 🔒 Sec
AC13: 未成年人相关敏感内容（涉校园欺凌、自伤）优先级最高，强制人工复核 · ⚖️ Comp
🔀
FR-4 · LLM 调用降级策略 P1
  • 依托 ai_gateway 模型池配置厂商优先级：通义 → 智谱 → 讯飞 → 豆包，逐一降级。
  • 全部失败返回预设模板兜底回答；超时中断、限流排队、审核失败默认放行 + 标记待复核。
  • 重试：最多 3 次、指数退避（1s/2s/4s）、超时 30s 可配置。
  • 监控指标暴露：成功率、平均响应时间、降级触发次数、Token 消耗（联动 D-10 运营监控）。
验收标准（AC）
AC14: 主模型故障时自动切换备用模型，用户无感知（响应内标注实际模型）· 🧩 API + 📊 Perf
AC15: 全链路失败时返回模板兜底 + 明确提示，不返回 500 白屏 · 🖐️ Manual
AC16: 每次调用（含降级轨迹）记录 ai_call_logs · 🧩 API
AC17: 降级触发次数、成功率指标可被监控系统采集 · 📊 Perf

04 · Business Flows

§4 业务流程定义

本章定义 D-09 的 4 条核心业务流程：用户旅程（RAG 问答）、状态机（Agent 会话）、跨模块交互（内容审核流水线）、异常流程（LLM 降级策略）。流程图使用 Mermaid 语法内嵌渲染，作为开发实现与测试用例设计的唯一流程基准。

4.1 · 流程 1：用户旅程 —— RAG 知识问答

覆盖从「用户提问」到「反馈闭环」的完整旅程（FR-1）。检索命中与否走不同分支；用户反馈回流知识库质量运营。

graph TD
    A[用户提问] --> B[ai_chat 接收问题]
    B --> C[问题向量化<br/>百川 Embedding]
    C --> D[检索知识库<br/>knowledge_chunks]
    D --> E{"相似度 > 阈值?"}
    E -->|是| F[取 Top-K 上下文]
    E -->|否| G[提示无相关知识]
    F --> H["构建 Prompt<br/>问题 + 上下文"]
    H --> I["调用 LLM<br/>通义千问/智谱 GLM"]
    I --> J[流式返回 SSE]
    J --> K[用户查看回答]
    K --> L{用户反馈}
    L -->|点赞| M[记录正向反馈]
    L -->|点踩| N[记录负向反馈 + 可选原因]
    G --> O[转人工或通用回答]

4.3 · 流程 3：跨模块交互 —— 内容审核流水线

时序图展示 ai_gateway、审核引擎、大模型服务、MySQL、notification 五方协作（FR-3）。规则预审负责快速拦截低成本违规；模型判定负责语义级风险；低置信/不安全内容进入人工复核队列。

sequenceDiagram
    participant User as 用户
    participant Gateway as ai_gateway
    participant Moderation as 审核引擎
    participant LLM as 大模型服务
    participant DB as MySQL
    participant Notification as notification

    User->>Gateway: 提交内容（作业/讨论/笔记）
    Gateway->>Moderation: POST /moderation/check
    Moderation->>Moderation: 规则引擎预审<br/>敏感词/正则/黑名单
    alt 规则命中
        Moderation->>DB: 记录 moderation_log (blocked)
        Moderation-->>Gateway: {passed: false, reason: "违规内容"}
        Gateway->>Notification: 通知用户内容被拦截
        Gateway-->>User: 返回错误提示
    else 规则未命中
        Moderation->>LLM: 调用内容审核模型<br/>通义/智谱 内容安全
        LLM-->>Moderation: {safe: true/false, confidence}
        alt 模型判定安全
            Moderation->>DB: 记录 moderation_log (passed)
            Moderation-->>Gateway: {passed: true}
            Gateway->>DB: 保存内容
            Gateway-->>User: 发布成功
        else 模型判定不安全
            Moderation->>DB: 记录 moderation_log (reviewing)
            Moderation->>Notification: 通知管理员人工复核
            Moderation-->>Gateway: {passed: false, reason: "待人工审核"}
            Gateway-->>User: 内容审核中
        end
    end

4.4 · 流程 4：异常流程 —— LLM 调用降级策略

触发条件：LLM 服务不可用或响应超时。降级决策树如下（FR-4），按优先级执行五级降级策略。

flowchart TD
    A[业务侧发起 LLM 调用] --> B{调用结果}
    B -->|成功| C[正常返回<br/>记录 ai_call_logs]
    B -->|异常| D{错误类型判定}
    D -->|"服务失败 / 5xx"| E["重试 ≤3 次<br/>指数退避 1s/2s/4s"]
    E --> F{主模型恢复?}
    F -->|是| C
    F -->|否| G["切换备用模型<br/>通义 → 智谱 → 讯飞 → 豆包"]
    G --> H{备用模型可用?}
    H -->|是| C
    H -->|否| I["返回预设模板回答<br/>提示「服务暂时不可用」"]
    D -->|"超时 30s+"| J["中断请求<br/>提示「响应超时 请重试」"]
    D -->|"限流 429"| K[排队等待]
    K --> L{等待内恢复?}
    L -->|是| C
    L -->|否| I
    D -->|"内容审核失败"| M["默认放行 + 标记「待复核」<br/>通知管理员"]
Flow 4 · LLM Fallback Strategy — Exception Flow（flowchart TD）

规则明细降级策略与重试参数

#触发条件降级动作优先级
1主模型调用失败切换到备用模型（通义 → 智谱 → 讯飞 → 豆包）最高
2所有模型失败返回预设模板回答 + 提示「服务暂时不可用」兜底
3超时（>30s）中断请求 → 提示「响应超时 请重试」—
4限流（429）排队等待 → 超时则返回降级回答—
5内容审核服务失败默认放行 + 标记「待复核」 + 通知管理员可用性优先

重试机制参数

  • 最大重试次数：3 次
  • 重试间隔：指数退避（1s → 2s → 4s）
  • 超时时间：30s（可配置）

监控指标（联动 D-10 运营监控）

  • 模型调用成功率
  • 平均响应时间
  • 降级触发次数
  • Token 消耗量
⚠️ 流程间约束
流程 3（审核）嵌套于流程 1/2 的生成出口：所有 RAG / Agent 对外输出内容同样需经审核链路（输出侧过滤）；流程 4（降级）作用于流程 1/2/3 中的每一次模型调用点（Embedding、生成、审核模型）。审核服务自身失败按策略 5 处理，不得因审核不可用而阻断核心教学功能。

07 · Compliance

§7 合规与数据保护
合规域适用法规本需求落地措施
AI 生成内容 《生成式人工智能服务管理暂行办法》 RAG / Agent 输出前端显式标注「AI 生成」；回答附带知识库引用来源可核查；训练与推理模型来源在模型池元数据中披露
内容安全审核 同上 · 《网络信息内容生态治理规定》 流程 3 三级流水线先审后发；审核日志留存 ≥30 天备查；复核入口管理员可追溯
个人信息保护 《个人信息保护法》 提问与会话数据最小化收集，仅用于服务本身；审核日志存内容摘要不落原文全量；支持用户查阅 / 删除自己的会话记录
未成年人保护 《未成年人保护法》《未成年人网络保护条例》 学生端内容强制走审核链路；涉未年成人敏感内容强制人工复核（AC13）；防沉迷时段内 AI 问答限流（与平台策略联动）
算法应用 《互联网信息服务算法推荐管理规定》 RAG 检索排序逻辑可解释（返回相似度分数与来源）；用户可在设置中关闭个性化知识库推荐
🔒 安全边界
Agent 代码执行工具必须沙箱隔离（无文件系统 / 网络越权，AC8）；数据库查询工具仅只读账号；审核服务自身失败时「默认放行 + 待复核」是可用性权衡，事后必须通过 stage 字段批量回扫。
