02 · 设计目标与原则 Goals

Architecture Principles

2.1 设计目标

目标量化指标技术策略
高可用SLA ≥ 99.9%（月度停机 ≤ 43 分钟）多可用区部署 · 服务熔断 · 自动扩缩容
低延迟API P95 ≤ 200ms · 直播 ≤ 2s边缘缓存 · 读写分离 · WebSocket 长连接
可扩展支持 10,000 并发用户单体应用 · 水平扩展 · 读写分离
跨端一致设计 Token 复用率 ≥ 95%Design System · 共享组件库 · 统一 API
AI 原生AI 功能响应 ≤ 3s（首 token）国产模型池 · 智能路由 · 流式响应
安全合规等保三级 · 个保法合规零信任 · 数据加密 · 审计追溯 7 年

2.2 设计原则

🎯 领域驱动

按教育业务领域拆分服务边界，避免技术驱动的过度抽象

📱 跨端优先

API-First 设计，前端三端共用同一套 RESTful + WebSocket 接口

🤖 AI 可插拔

AI 能力抽象为统一接口层，底层模型可热切换，支持多厂商并行

🔒 默认安全

零信任网络 · 最小权限 · 全链路加密 · 审计日志不可篡改

📊 可观测

Metrics + Tracing + Logging 三位一体，问题 5 分钟内定位

💰 成本可控

智能路由分流 · 多级缓存 · 模型按需选择，AI 成本降低 60%+

06 · 数据库设计 Database

MySQL 9.7 · 单库模型

6.1 核心数据模型

-- 用户表
CREATE TABLE users (
  id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  student_id  VARCHAR(20) UNIQUE,      -- 学号
  name        VARCHAR(50) NOT NULL,
  role        ENUM('student','teacher','admin'),
  department  VARCHAR(100),
  created_at  TIMESTAMPTZ DEFAULT now()
);

-- 课程表
CREATE TABLE courses (
  id          UUID PRIMARY KEY,
  code        VARCHAR(20) UNIQUE,      -- 课程编号
  title       VARCHAR(200) NOT NULL,
  teacher_id  UUID REFERENCES users(id),
  credits     DECIMAL(3,1),
  semester    VARCHAR(20),              -- 2026-1
  status      ENUM('draft','published','archived')
);

-- 作业表（含 AI 批阅字段）
CREATE TABLE assignments (
  id            UUID PRIMARY KEY,
  course_id     UUID REFERENCES courses(id),
  title         VARCHAR(200),
  due_at        TIMESTAMPTZ,
  ai_grading    BOOLEAN DEFAULT false,  -- 启用 AI 辅助批阅
  rubric        JSONB,                  -- 评分标准
  ai_model      VARCHAR(50)             -- 指定 AI 模型
);

6.2 数据分片策略

数据表分片键策略预计规模
users—不分片（1,500 用户）< 1 GB
coursessemester按学期分区~ 500 门/学期
submissionscourse_id按课程哈希分片10 万+/学期

09 · 安全设计 Security

9.1 安全架构

🔐 身份认证

JWT + Refresh Token 双令牌
Access Token 15 分钟过期
管理员强制 2FA（TOTP）
单设备登录 · 异地检测

🛡️ 权限控制

RBAC 角色 × 资源 × 操作
数据级权限（学生只看自己）
ABAC 属性策略（院系/学期）
API 级别鉴权中间件

🔒 数据加密

传输 TLS 1.3 · HSTS
存储 AES-256（敏感字段）
密码 bcrypt · 12 轮
密钥 KMS 托管 · 定期轮换

🕵️ 审计追溯

全操作日志 · 不可篡改
日志保留 7 年（合规要求）
敏感操作实时告警
AI 决策全链路追溯

🌐 网络安全

WAF · DDoS 防护
VPC 网络隔离
服务网格 mTLS
SQL 注入 · XSS · CSRF 防护

🤖 AI 安全

输入/输出内容审核
Prompt 注入检测
学生数据不用于训练
AI 决策可解释性报告

9.2 合规要求

法规要求技术措施
等保三级身份鉴别 · 访问控制 · 安全审计2FA · RBAC · 审计日志

15.2 Git 工作流

# 分支策略：Git Flow
main         ← 生产分支 · 受保护
  └── develop    ← 集成分支
       ├── feature/  ← 功能分支
       ├── fix/      ← 修复分支
       └── release/  ← 发布分支

# Commit 格式
feat(auth): add OAuth2 login
fix(course): resolve N+1 query
docs(api): update endpoints

15.3 Code Review

Review 规则
✓ 所有合并到 develop/main 必须经过 PR + 至少 1 人 Approve
✓ CI 测试通过率 100% · 覆盖率 ≥ 80%
✓ 安全扫描无高危漏洞
✓ AI 相关变更需 AI 团队 Approve

18 · 附录 · 术语表 Glossary

Appendix
术语定义
SLAService Level Agreement，服务等级协议，定义可用性指标（如 99.9%）
RPO / RTORecovery Point Objective（数据丢失容忍度）/ Recovery Time Objective（恢复时间目标）
RAGRetrieval-Augmented Generation，检索增强生成，结合知识库提升 LLM 准确性
SFUSelective Forwarding Unit，WebRTC 视频架构，选择性转发媒体流
CRDTConflict-free Replicated Data Type，无冲突复制数据类型，用于实时协同编辑
mTLSmutual TLS，双向 TLS 认证，服务间通信加密 + 身份验证
ReActReasoning + Acting，AI Agent 推理-行动循环范式
Design Token设计令牌，存储视觉设计决策（颜色/字体/间距）的最小单元
